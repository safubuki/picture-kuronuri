# チャット画面の黒塗り改善レポート

**日時:** 2026年10月10日（日本時間）  
**対象:** Teams・Slackなどのチャット画面  
**深刻度:** Major（本文や操作アイコンの誤検出、黒塗り位置のずれ）  
**比較基準:** `509c5caa1dffd85d8d6079940ecc02f3481f52db`

## 原因と修正

| 問題 | 原因 | 実装した改善 |
|---|---|---|
| イニシャル・操作アイコンを消す | 円形やコントラストだけでアバターと判定。サンプル座標を画像未確認で採用 | 写真の色階調・肌・背景分離を確認。事前座標も内容を検証し、OCR本文へ重なる独自候補を除外 |
| サイドバー付き画面の写真を見逃す | 独自探索が左右端だけ | OCR行の左隣へ上限付き探索を追加。小さい写真も行高から推定 |
| 写真の枠が周辺へ広がる | 探索窓をそのまま黒塗りに使用 | 背景に接続する画素を調べ、写真の輪郭へ枠を合わせる |
| 見出し・地名・挨拶を人名扱い | 名字の全位置部分一致、無条件の姓名推定、短文の送信者推定 | 名前の境界・敬称・氏名ラベル・送信者配置を確認。挨拶は元文の範囲で除外 |
| 似た文章も消す | 同定した名前と1文字違いの文字列を文書全体へ伝播 | 正規化した同名だけを検索。名前が地名や別の単語へ含まれる場合も除外 |
| 無関係な場所へ枠がずれる | 共有する文字矩形の二重縮尺変換、UTF-16と文字数の不一致、空白除去後の座標不整合 | 矩形を一度だけ変換し、絵文字・拡張漢字・空白処理後も原文位置へ対応 |
| 一部分の人名で行全体を消す | シンボル不一致時に単語全体を採用 | 原文と単語を対応させ、単語内の該当部分だけを推定 |
| 重なった枠が巨大化する | 小さい枠の35%重複だけで外接矩形へ統合 | 同じ行の十分な重複・包含だけを統合。写真と文字、別行の交差は維持 |
| 再解析が遅い／古い結果が混ざる | 写真探索・傾き検出の繰り返し、非同期解析の競合 | 同じ画像の写真結果・傾き角を再利用。解析を直列化し、切り替えた画像の古い結果を破棄 |
| OCR前処理が重い | 画素ごとの同じ補間計算、境界処理、再試行時の画像解析 | 補間係数を事前計算し、境界と内部を分離。代替OCRで元の画像解析を再利用 |

再利用した実OCRにも初回と同じ文字位置調整を適用します。文字位置の画素探索は候補の周辺へ限定し、写真だけなら行いません。人名と連絡先の検出スイッチは、ラベル付きの氏名にもそれぞれ適用します。

## 測定結果

写真候補検出は400×700の固定合成画像、Canvasモック、ウォームアップ5回＋25標本の中央値です。CanvasのCPU処理部分の比較であり、実画像の精度やOCRを含む全体の処理時間を示す値ではありません。

| 合成画像 | 旧版 | 改善後 | 旧版の検出 → 改善後 |
|---|---:|---:|---|
| 青・橙・灰のイニシャル | 17.990 ms | 6.426 ms（約2.80倍） | 誤検出6枠 → 0枠 |
| 左右の写真特徴 | 10.341 ms | 6.580 ms（約1.57倍） | 左側の不正確な3枠 → 左右の正しい2枠 |
| 無地 | 22.971 ms | 5.610 ms（約4.09倍） | 0枠 → 0枠 |
| サイドバー・中央写真 | 23.252 ms | 7.899 ms（約2.94倍） | 見逃し → 正しい1枠 |
| サイドバー・中央イニシャル | 24.907 ms | 7.033 ms（約3.54倍） | 0枠 → 0枠 |

写真探索のCanvas作成は4回から1回、画素読取りは2回から1回になりました。回帰テストの小／大・丸／四角・中央列の合成写真では、期待する写真の枠に対してIoU > 0.9を確認しました。

OCR前処理はNode.js 22.19.0、2000×1500の固定seed画素、ウォームアップ4回＋旧新版の順序を交互にした11標本の中央値です。

| 処理 | 旧版 | 改善後 | 短縮率 |
|---|---:|---:|---:|
| CLAHE（局所コントラスト調整） | 33.77 ms | 26.04 ms | 22.9% |
| Gaussianフィルター | 59.38 ms | 51.08 ms | 14.0% |

35通りのサイズ・設定で、改善した前処理の出力画素が旧版と完全一致することを確認しました。低信頼のOCRを再試行する条件・試行回数は維持しています。時間は端末と負荷で変わります。

## 現時点の制限

- 実際のTeams・Slack画像を用いた適合率・再現率、OCRを含む全体の速度は未測定です。
- ネイティブ顔検出を使用できない環境では、モノクロ・肌の少ない写真・複雑な背景の写真には見逃しが残り得ます。中央列の写真探索にはOCR座標が必要です。
- 未知の名前やusernameは、氏名ラベルまたは送信者の配置が必要です。誤検出を抑えるため、文書全体での1文字違いの名前の推定は行いません。
- ラベルなしで自治体名・番地区切りを省略した住所は見逃す場合があります。住所ラベルと帳票配置による検出は維持しています。

実画像での評価を追加する際は、写真・イニシャル・通常の本文・本物の個人情報を含む正解枠を用意し、誤検出と見逃しの両方、初回と再解析の時間を比較します。
