# OCR読み込みのタイムアウト改善

**対象:** 初回読み込み時の文字行検出と、自動黒塗りの文字認識  
**バージョン:** 0.0.0（package.json）  
**深刻度:** Major（文字行ガイド・行スナップを利用できない）  
**状態:** 実装修正・回帰テスト完了。報告対象の実ファイルによる確認は未実施。

## 現象と原因

複雑なファイルの読み込み時に文字行検出がまれにタイムアウトし、同じファイルを2〜3回読み込むと成功するとの報告。

`src/engine/ocr.ts` は通常の認識を25秒、低信頼時の追加認識を12秒で打ち切っていた。認識が進行中でも、画像の複雑さや端末の処理速度によらず終了していた。また、通常認識のタイムアウト時にはWorkerを破棄して結果を返すだけで、読み込み操作内での自動再試行はなかった。

この実装は報告された症状と整合する。ただし、対象ファイル・端末の実行ログがないため、実際の失敗原因すべてを確定したものではない。

| 問題 | 対応 |
|---|---|
| 処理が進んでいても25秒／12秒で打ち切る | 両方の認識を、45秒の進捗停止監視と1回あたり1分の上限へ変更 |
| 一時的な停止・認識エラーのたびに読み込み直す必要がある | Workerを破棄・再生成して、同じ入力を1回自動再試行 |
| 追加認識がタイムアウトしても「文字なし」になる | 初回に文字がなければtimeoutを返し、文字があれば初回結果を保持して警告 |

## 実装方針

- 進捗の数値が増えた時だけ停止監視を更新する。同値・逆行・不正値・別ジョブの通知では延長しない。
- 1分の上限は進捗にかかわらず適用する。通常認識・追加認識の各試行が対象で、自動再試行・Workerの初期化・画像前処理を含む全体の制限ではない。
- 再試行で画像を縮小し直さず、前処理済みの画像と座標縮尺を再利用する。正常時は従来どおり1回で完了し、待ち時間を追加しない。
- 完了・失敗時は監視タイマーと進捗リスナーを解除し、停止したWorkerをキャッシュから取り除く。追加認識後は通常の認識モードへ戻す。
- 時間がかかっている場合と自動再試行時に、画面へ状況を表示する。

固定の制限時間だけを延長する案では、処理が進んでいるケースと停止したケースを区別できないため、進捗監視を併用した。

## 対応・検証

- [x] 通常認識と追加認識のタイムアウト制御を共通化
- [x] 停止・エラー時のWorker再生成と自動再試行
- [x] 回帰テスト9件追加（既存11件と合わせOCR20件）
- [x] `npm.cmd test` 成功（全7スイート）
- [x] `npm.cmd run build` 成功（TypeScript・Vite・PWA生成）

追加テストでは仮想タイマーとWorkerモックを使い、40秒の初回認識、進捗が続く55秒の認識、45秒間の停止、1分の上限、再試行の成功・再停止、認識エラー、30秒の追加認識、追加認識失敗時の初回結果保持を確認した。成功後にタイマーが残らず、Workerの再利用と文字座標を維持することも確認した。

これらの秒数はテストで再現した経過時間であり、実画像の処理時間を測定した値ではない。任意の画像・端末で初回成功を保証するものではなく、実ファイルでの成功率・処理時間は未測定。
