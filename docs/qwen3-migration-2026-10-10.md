# Qwen3 0.6Bへの移行

日付: 2026-10-10

- モデルを `onnx-community/Qwen3-0.6B-ONNX` に変更。
- Transformers.js v4の `tokenizer_encode_kwargs.enable_thinking=false` を使い、清書・キーワード抽出の両方で思考モードを無効化。
- `shader-f16` 対応WebGPUでは `q4f16`、それ以外では `q4` を使用。GPU初期化失敗時はCPU用 `q4` に切り替える。
- 初回取得量の通常時目安を約600～950MBに修正。GPUからCPUへ切り替わる場合は、追加取得が発生し得る。
- 初期化中の要求は同じPromiseを待ち、30秒を超える取得でも二重初期化を防ぐ。
- 旧Qwen2.5や設定ファイルだけの保存を、Qwen3保存済みと判定しない。削除では旧新のLLMをまとめて対象とし、OCRデータを残す。
- 設定説明を、実際に呼び出される「文章清書・伏字化」に合わせる。画像の自動黒塗りへのLLM接続は今回の変更には含めない。

## 検証結果

- `npm test`: 84件成功。今回追加したLLM回帰8件、キャッシュ回帰15件を含む。
- `npm run build`、`git diff --check`: 成功。
- 実Chrome/WebGPU (`shader-f16` 対応) でモデルの読み込みに成功。
- 実トークナイザーの思考OFFテンプレートを確認。
- 日本語入力 `メール: test.user@example.com` に対する実生成は `[メールアドレス]`。思考ブロックの出力なし。
- 保存失敗時の画面案内を実ブラウザで確認。未保存表示、有効状態の維持、残存データの削除ボタンを確認。
- CPUへの切り替えは回帰テストで確認。実CPU推論の速度・精度は未測定。

## 検証環境での保存制限

実検証ブラウザーでは、設定・トークナイザー・WASMは保存されたが、約570MBの重みへのCache API書き込みが `UnknownError: Unexpected internal error` で失敗した。推論は動作し、保存状態は正しく未保存と判定した。

ブラウザーの報告する容量上限は約10.7GB、使用量は約32MBで、原因は特定できていない。通常の保存成功・オフライン再読み込みは、この環境では確認できていない。

保存に失敗した場合は、利用可能な状態と保存済み状態を分け、次回の起動で再取得が必要なことを画面で案内する。モデル変更による日本語チャットの黒塗り精度改善率は未測定。
